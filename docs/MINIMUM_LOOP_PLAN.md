## 首个真机闭环验收矩阵

### 原生性及世界碰撞

- DC 保持前台，MC 后台消费带 sequence 的左右/跳跃按下和松开；原生输入状态、集成服务器玩家 tick 和原生碰撞结果可读回。
- 用 DC 实际地面、实墙、平台边缘测试行走、急停、转向、跳跃、落地；不得每帧覆写 MC 坐标来掩盖墙穿透。
- 断开/移除原超平坦干扰的证据明确；同一操作在有/无原世界不同地形时不得改变桥接结果。
- DC 载体与 MC 解算位置只有一个权威运动源；原 Hero 不二次重力、移动、攻击或结算伤害。相机和世界身份仍属于真实 Hero。

### 真帧与空间配对

- MC 原生渲染当前玩家及动作到透明目标，DC 内部世界图层绘制随脚底锚点移动。固定画面或静态帧不能通过。
- 原版 MC 背景不进入玩家层；记录 alpha、Y翻转、预乘混合、特效范围和分辨率，黑边/雾分别定位。
- 人物临时姿态/回切不改变站立参考比例。
- frameId/pose/nativeTick/inputSeq/epoch配对；故意延迟 GPU 读回时不得用旧帧更新新位置。读取忙只丢显示采样，不形成视频积压。

### 所有权、故障、恢复

- 站立、跳跃、落地前后、按键保持时按 F7：仅一个玩家逻辑拥有输入，切回 Hero 后重力/碰撞/可见性/交互恢复，不能漂浮或粘键。
- 断开 guest、暂停/失焦、切关、同LevelId重新生成、错误版本、IPC溢出、半写槽、helper异常退出：释放输入并安全返回Hero，不永久无敌，不使用旧epoch。
- 不关闭玩家自己启动的游戏；日志记录每次退出和恢复是否完成。

### 端到端记录

输入采集 → MC消费 → 原生物理提交 → GPU采集/读回完成 → DC纹理上传/绘制 → host present返回，分别记录 tick/帧序号。给出 p50/p95/p99、最大值、丢帧、帧龄与队列深度，报告样本数、热/冷场景和基线。当前不设未经测量的“一帧延迟已通过”结论。

## 最终三维产品额外验收

- 可旋转视角和第一/第三人称切换；墙体有可观察厚度、正确门洞、楼层和侧背面，无只在正面成立的纸片几何。
- MC 深度方向运动受实际三维碰撞解算；DC 敌人/攻击/交互的深度范围得到实际识别，不在隔着Z距离时误命中或穿门触发。
- 创建/摧毁可编辑块后，MC原生世界与DC世界身份/碰撞/显示一致。保护区或未支持原墙体编辑要明确拒绝，不用视觉消失冒充真实世界修改。
- 三维模式结束可以回到原Hero和正常DC关卡；MC block ledger、关卡重载和存档策略必须定义并验证。
