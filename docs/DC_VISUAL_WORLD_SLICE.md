# DC 场景外观与 MC 玩家渲染边界

用户本轮明确的目标是：DC 窗口内的三维 DC 世界，只保留 MC 的 UI、手臂和装备；玩家运动、库存、挖放和战斗由原生 MC 驱动。前后台各开一款游戏或显示 MC 石头场景不满足此目标。

本片先纠正世界显示来源。继续使用真实 DC 格网生成的有厚度原生碰撞体和原生 MC 渲染器；世界表面取自用户安装的 DC prison 图集，MC 天空、云、天气和原世界实体不得进入场景。提取与转换素材留在工程外，只交付转换器、适配代码和来源摘要。资源包不是敌人、交互或世界编辑同步的替代品。

边界：现有几何仍是有来源证明的局部实体子集，未支持格子不补成墙；材质是显式选择的 prison 主题，不能声称恢复了 DC 原场景逐格装饰、灯光和背景层。原生第三人称相机必须保留，但 MC 身体应在世界层剔除；DC 角色和装备的完整三维显示另行验收。库存内的 MC 人物预览属于原生 UI。

进入前核对原生场景摘要、资源包摘要、实际已选择的包和材质资源来源，以及当前 DC 图集身份。图集不匹配时拒绝接管。显示抑制只在本次场景有效期生效；恢复时撤销，不改全局渲染设置。

验收必须同时有：DC 前台原生走跳及转向、真实 DC 材质覆盖厚度的多面图像、MC 天空和实体剔除、真实 GPU→DC 上传配对、F7 返回与方块全量回滚。编译、Knot 变换或转换器检查只分别证明各自范围，不构成游戏内通过。

目前已通过本机 DC 20 张 24×24 材质转换、10 个完整立方体模型检查、确定性资源包重复生成，以及 Java25 实际 Knot/Mixin 的提取、天空、两种云 pass 和雾钩子变换。实际原生渲染状态夹具证明：未启用时不剔除实体，启用时清除原生世界实体但保持手臂/GUI 引用，释放后恢复实体资格。DC 原生启动守卫正例和缺失加载器反例通过。原生帧记录增加捕获时的世界外观来源标记；本片可选最大边 1024，仍是有界的实验帧率。
